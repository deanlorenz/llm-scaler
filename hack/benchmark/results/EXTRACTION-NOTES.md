## What changed in session 4 (Sub-task 12)

### Histogram bucket extraction — `parse_vllm_scrape`

Four new `_bucket` metric families are parsed from vLLM pod scrape files:

| Internal key | vLLM metric |
|---|---|
| `ttft_buckets` | `vllm:time_to_first_token_seconds_bucket` |
| `out_tok_buckets` | `vllm:request_generation_tokens_bucket` |
| `in_tok_buckets` | `vllm:request_prompt_tokens_bucket` |
| `qwait_buckets` | `vllm:request_queue_time_seconds_bucket` |

Raw cumulative bucket vectors are stored as `result["bkt"][key] = {le_float: count}`.
`+Inf` boundaries are excluded. If bucket lines are absent, `bkt` is empty — no traceback.

### `pod_series` — delta histogram emission

For each consecutive scrape pair `(a, b)`, the cumulative bucket vectors are differenced:
`delta[le] = b.bkt[key][le] - a.bkt[key][le]`

- If any `delta[le] < 0`: pod restarted → `null` for that histogram
- If `sum(deltas) == 0`: no new observations → `null`
- Otherwise: `{"le": [...], "n": [...]}` — sorted finite boundaries + per-bucket delta counts

New fields in `pods[].series[]`:
```json
"ttft_hist":    {"le": [0.001, 0.005, ..., 2560.0], "n": [0.0, 0.0, 15.0, ...]},
"out_tok_hist": {"le": [1.0, 2.0, ..., 20000.0], "n": [...]},
"in_tok_hist":  {"le": [1.0, 2.0, ..., 20000.0], "n": [...]},
"qwait_hist":   {"le": [0.3, 0.5, ..., 1920.0], "n": [...]}
```

The existing `ttft_ms` (mean from sum/count diff) is unchanged alongside the new histogram fields.

### `_hist_percentile` helper

New function: `_hist_percentile(le_list, n_list, q)` — linear interpolation within buckets
to compute the q-th percentile (0–100) from a delta histogram. Used by the back-fill.

### `ttft_p50` back-fill in `requests.json`

For inference-perf runs where the harness does not record per-request TTFT, `ttft_p50` in
`requests.json` buckets was always null. Sub-task 12 fills it from pod-scrape histograms:

- `backfill_ttft_p50(requests_buckets, pods, load_start_epoch)` runs after `pods` is assembled
  but before `requests.json` is written.
- Only fills buckets where `ttft_p50 is None` AND `dep_rate > 0` (no overwrite of guidellm data;
  arrival-only buckets left null since TTFT is undefined without departures).
- For each qualifying bucket, finds the pod-series interval whose right-edge covers the bucket
  midpoint, then computes `ttft_p50` via `_hist_percentile` and sets `source = "vllm-scrape"`.
- Falls back to nearest interval when no exact-cover interval exists.

Result: 100% of dep_rate>0 inference-perf buckets now have non-null `ttft_p50`. guidellm buckets
remain `source=guidellm` untouched.

## What changed in session 3

### Problem 1 — Replica deduplication
- `_dedup_replicas()` helper added: consecutive duplicate entries suppressed per source
- Harness source: deduplicates on `(desired, ready, available)`
- WVA source: deduplicates on `(current_replicas, kv_capacity_tokens, capacity_per_replica)`
- First and last record per source always kept (renderer anchor + step-line right edge)
- Result: quick-smoke went from 64 → 4 replica records; burst-variant1 from 1,242 → O(scale events)

### Problem 2 — Replica window sentinels in `meta.json`
Four new fields added to `meta.json` after all data is assembled:
- `load_end_t` — planned load end (= `load_duration_s`, seconds from load start)
- `last_departure_t` — t of last bucket midpoint in `requests.json` (max observed departure)
- `last_scale_event_t` — t of last `scaler[]` event across all SOs
- `replica_scrape_end_t` — t of last replica record emitted across all SOs and sources

Pathological case now visible: `early-inference-perf` has `replica_scrape_end_t: 57190`
vs `load_end_t: 180` — scraper ran 16 hours past load end. Viz can clip x-axis to
`max(last_departure_t, last_scale_event_t)` with `load_end_t` as minimum floor.
No data is truncated by the extractor.

### Problems 3 & 4 — Pod scrape metric table fixes
New metrics captured in `pods[].series[]`:

| Field | Source metric | What it is |
|-------|--------------|-----------|
| `ok_rate` | `vllm:request_success_total` (summed across `finished_reason` labels) | Completed request rate (req/s) |
| `gen_rate` | `vllm:generation_tokens_total` (counter diff) | Output token rate (tokens/s) |
| `ttft_ms` | `vllm:time_to_first_token_seconds` (histogram diff) | Mean TTFT ms per interval |
| `e2e_ms` | `vllm:e2e_request_latency_seconds` (histogram diff) | Mean e2e latency ms per interval |
| `prefill_ms` | `vllm:request_prefill_time_seconds` (histogram diff) | vLLM-internal prefill batch time ms |

Naming fix: `prefill` histogram was previously mapped to `vllm:time_to_first_token_seconds`
(wrong). Now correctly: `ttft` → TTFT, `prefill` → prefill batch time.

`ok` counter handling: `vllm:request_success_total` carries a `finished_reason` label
(`stop/length/abort/error/repetition`). Parser sums all label values before differencing
so `ok_rate` represents total departures per second.

`out_tok` and `ttft_ms` on per-request `requests.json` records remain null for
inference-perf — that harness does not report them per-request. The timeseries
equivalents (`gen_rate`, `ttft_ms`) are now in `pods[].series[]` where they belong.

### Sub-task 11 — requests.json redesign: aggregated timeseries (complete)
- `MAX_REQUESTS` cap and raw per-request record schema removed
- `requests_to_contract()` replaced with `requests_to_buckets()` — one streaming pass
- `infer_requests_from_scrapes()` removed (synthesised fake records, no longer needed)
- `--head` flag removed; `--bucket-width S` added (default: 1.0s)
- New bucket schema per the viz contract:

```json
{
  "t":        <bucket midpoint, seconds from load start>,
  "arr_rate": <arrivals/s>,
  "dep_rate": <departures/s>,
  "in_system": <mean L(t) — requests in flight>,
  "n_waiting": <count of departures with a recorded ttft>,
  "frac_fast": <fraction of departures with e2e < 2s>,
  "ttft_p50":  <median TTFT ms, null if no source>,
  "source":    <"inference-perf" | "guidellm" | "vllm-scrape">
}
```

- guidellm has real `ttft_p50` from harness (e.g. 25ms). inference-perf gets it from pod scrapes.
- `frac_fast` uses e2e < 2s threshold (same as old viz `WAIT_EDGES`)
