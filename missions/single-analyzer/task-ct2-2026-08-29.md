# Task CT2 — replace `AnalyzerResults []NamedAnalyzerResult` with a single `CompositeSignal` field

**Mission:** single-analyzer. **Spec:** `spec-composite-metric-and-optimizer-t2.md` (CT2
section), on `session-tracking`, `missions/single-analyzer/`.

**Branch:** `single-analyzer`. This task's diff must be self-contained and land as its own
commit — do not touch anything scoped to CT3/CT4/CT5.

## Intent

`runAnalyzersAndScore` (`internal/engines/steadystate/engine_v2.go`) already returns a
length-1 `[]allocation.NamedAnalyzerResult` today — T1's compose step guarantees exactly one
entry, always named saturation (in the sat-only default) or whatever `composeAnalyzerResults`
picks. `saturationNamedEntry`'s linear search by name is therefore vestigial in production.
This task stops wrapping that already-single entry in a slice and stops every consumer
searching for it by name — it does **not** change what value flows through, only its type.

## Expected outcome

- `ModelScalingRequest.AnalyzerResults []NamedAnalyzerResult` → `ModelScalingRequest.CompositeSignal NamedAnalyzerResult`
  (value, not pointer) in `internal/engines/allocation/optimizer_interfaces.go`.
- `saturationNamedEntry` (`internal/engines/allocation/analyzer_helpers.go:87-101`) is deleted.
- No remaining reference to `saturationNamedEntry` or `.AnalyzerResults` anywhere in
  `internal/engines/allocation/` or `internal/engines/steadystate/` (including tests).
- Full existing test suite passes, zero regressions.
