## CT6 design discussion — 2026-08-31

### estimateSchedulerQueueDemand — resolved

Traced the saturation analyzer's Analyze() call (analyzer.go lines 112–132). Key findings:
- estimateSchedulerQueueDemand is **internal to the sat analyzer**, computed before the result is returned. TotalDemand and RoleDemand the engine receives already include it — there is no separate signal.
- Units: KV-tokens throughout. QueueDemand = (inputTokens + outputTokens) from EPP queue size × avg request shape, role-attributed (prefill=input, decode/both=input+output). Same token unit as occupancy demand from live replicas and as PRC from estimateStoredCapacity.
- Partial-SFZ case: decode replicas=0, PRC comes from estimateStoredCapacity (stored/derived capacity in tokens). RoleDemand[decode] includes queue-attributed tokens. Both in same token unit → PRC / RoleDemand[decode] is a valid dimensionless fraction.
- **CT6 pre-implementation verification: RESOLVED. Division is safe for partial-SFZ.** No formula adjustment needed.

### rescaleInput.Demand — analysis

Rescale is a **GPU-budget redistribution pass** that runs only when the cluster is GPU-contended (totalDemandGPUs > available). It water-fills a GPU budget across competing models using weights = priority × Demand. CapGPUs is the model's ceiling (demand-in-GPUs); a model capped early returns its excess to the pool.

The "last 1% of a huge model forcing out a small model" concern: **not a real risk**. CapGPUs (= modelDemandGPUs = replicas-needed × GPUsPerReplica) corrects over-allocation immediately — a model gets at most what it actually needs. The weight only affects who gets the uncapped share first.

Three options:
1. **Raw TotalDemand (today):** unit = tokens. Implicit assumption: all models have comparable PRC (same GPU cost per token). Breaks down with multi-variant or heterogeneous deployments. Also breaks after CT6 (TotalDemand=1.0 for all → priority-only).
2. **Priority-only (CT6 passthrough):** weight = priority. Equal-priority models get equal GPU shares regardless of size.
3. **modelDemandGPUs (replicas_needed × GPUsPerReplica):** weight = GPU footprint of the model's actual demand. Already computed on rescale.go:552. Numerically identical to today pre-CT6 (roleDemandGPUs already converts via bestPRC). Survives CT6 normalization because ceil(1.0 / coverage_best) × GPUs = same value as ceil(rawDemand / rawPRC) × GPUs. Most principled: distributing GPUs, weight by GPUs-needed, no token-unit assumption.

**Decision: leaning toward option 3 but user wants to think further.** Not yet committed. Recorded in CT6 spec open-decision section. CT6 implementation blocked until this is resolved.
