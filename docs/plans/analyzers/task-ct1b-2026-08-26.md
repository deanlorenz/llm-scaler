# Task CT1b — engine-side guard: saturation producing no result is a critical, abstain-worthy error

**Intent.** `runAnalyzersAndScore` (`internal/engines/steadystate/engine_v2.go:103-186`) calls
`runV2AnalysisOnly` to get saturation's raw result:
```go
baseResult, err := e.runV2AnalysisOnly(ctx, modelID, namespace, replicaMetrics, config,
    variantStates, scaleTargets, variantAutoscalings, schedulerQueue, arrivalRate)
if err != nil {
    return nil, err
}
```
If `err != nil`, this already bails correctly. But there is no check on `baseResult` itself when
`err == nil` — if `baseResult` were ever `nil` despite a nil error, the very next lines
(`baseResults := []rawAnalyzerResult{{name: domain.SaturationAnalyzerName, result: baseResult,
...}}`, then `composeAnalyzerResults`, then `buildNamedResult`) would proceed with a nil
`Result` baked into the entry — a silent bad state, not a caught error. Saturation's result is
the one every optimizer-side critical accounting (GPU quota usage, scale decisions) currently
assumes is always present and non-nil (see `docs/plans/analyzers/optimizer-call-map-2026-08-25.md`
and `composite-entry-spec-2026-08-25.md`). This task makes that assumption an explicit, checked
invariant at the point it's produced, rather than leaving it implicit.

**Mechanism — already resolved, do not reinvent** (see
`docs/plans/analyzers/resolved-open-items-2026-08-26.md` §1 and
`spec-composite-metric-and-optimizer-t2.md`'s CT1b section, v5): "critical" in this codebase's
own vocabulary means "abstain from a decision for this model, log/event/metric it, keep
processing every other model" — NOT a panic or crash. The existing, uniform pattern for exactly
this is one level up the call stack, in `internal/engines/steadystate/engine.go:980-1003`:
```go
req, err := e.collectV2ModelRequest(...)
if err != nil {
    msg := "V2 analysis failed"
    logger.Error(err, msg, "modelID", modelID)
    e.recordOptimizationFailedEvent(modelVAs, msg)
    e.emitSafetyNetMetrics(ctx, modelVAs, currentAllocations, data.scaleTargets)
    continue
}
```
`collectV2ModelRequest` calls `runAnalyzersAndScore` internally and propagates any error it
returns. **This means CT1b needs zero new logging/event/metric code in `engine_v2.go` — a plain
`error` return from `runAnalyzersAndScore` is sufficient; the caller two levels up already does
the full abstain sequence for any error from this function, today, unconditionally.**

**Reachability — confirmed unreachable today, so this is a pure defensive addition with no
behavior change on any current path** (`resolved-open-items-2026-08-26.md` §1): traced
`SaturationAnalyzer.Analyze` — every early return pairs a `nil` result with a non-nil `error`;
it never returns `(nil, nil)`. So the new branch below cannot fire via any real analyzer call
today. It exists to make a future violation of that contract loud (an error, caught by existing
machinery) instead of silent (a nil `Result` field quietly flowing into `composeAnalyzerResults`
→ `buildNamedResult` → the optimizer).

**Expected outcome(s).** `runAnalyzersAndScore` returns an explicit error
(`fmt.Errorf("saturation analyzer produced no result for model %s", modelID)` or equivalent
wording) when `baseResult == nil` and `err == nil` from `runV2AnalysisOnly`, instead of
proceeding to build a composite entry with a nil `Result`. Verified by: (a) a new unit test that
exercises this branch directly using a test double that deliberately violates
`SaturationAnalyzer`'s real contract (returns `nil, nil`), asserting the sentinel error is
returned and `composeAnalyzerResults`/`buildNamedResult` are never reached; (b) the full existing
test suite passes unchanged — this addition must not alter any currently-passing test's outcome,
since the branch is unreachable by every existing input.
