# Task CT1a — nil-guard `rescaleModelDecisions` against a missing saturation entry

**Intent.** `rescaleModelDecisions` (`internal/engines/allocation/rescale.go:336-...`, the call
at line 344-345) dereferences `satNamed.Result` immediately after
`saturationNamedEntry(req.AnalyzerResults)` with no nil-check — unlike its sibling function
`rescaleInputsForGroup` in the same file (line 525-526), which already guards this exact case
correctly:
```go
satNamed := saturationNamedEntry(req.AnalyzerResults)
if satNamed == nil || satNamed.Result == nil {
    continue
}
```
This is currently safe only via an implicit, cross-function invariant (nothing upstream
guarantees it, it just happens to hold today). Fix the fragile spot now, independent of and
before any larger restructuring (CT2 will touch this same file next), so later work builds on
solid ground.

**Verified already, no need to re-derive:** `spec-corrections-verification-2026-08-25.md` Q1
(and ledger §33) confirmed this fix is safe exactly as scoped — `rescaleModelDecisions`'s only
caller (`rescale.go:308`, inside `GreedyByScoreOptimizer`'s rescale pass) plain-appends its
return value (`decisions = append(decisions, d...)`) to a shared slice across all models in the
group. Returning `nil` for one model is an isolated no-op for that model only; it does not
affect any other model's decisions, and does not interact with per-variant scale-from-zero logic
(that logic lives elsewhere and doesn't call this function).

**Expected outcome(s).** `rescaleModelDecisions` has an explicit nil-check on `satNamed`
immediately after the `saturationNamedEntry` call, before any dereference, mirroring
`rescaleInputsForGroup`'s existing pattern exactly (same condition, same "bail out for this one
model" semantics — `return nil` here, since this function returns
`[]domain.VariantDecision` rather than `continue`ing a loop). Verified by a new test that
calls `rescaleModelDecisions` with a `ModelScalingRequest` whose `AnalyzerResults` has no entry
named `domain.SaturationAnalyzerName`, and asserts it returns `nil` (or an empty slice) rather
than panicking.
